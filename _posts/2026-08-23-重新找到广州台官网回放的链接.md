## 原来的官网回放

之前从“花城+”APP内置的分享链接功能，拿到了单个回放的页面的链接：
```
https://share.gztv.com/plusshare/#/articleDetail?id=按时间递增的十六位数字
```
进而顺藤摸瓜找到整个栏目的回放列表页面：
```
https://app.gztv.com/plusshare/#/topicDetail?id=五位数字
```

## 官网回放链接全部跳转APP下载？甚至没有“在APP中打开”？？

但是昨天发现上述网址都直接跳转到腾讯应用宝的“花城+”APP下载页面了，以至于APP里的分享功能分享了个寂寞，因为无论是QQ微信微博还是复制链接，外部打开通通跳转APP下载

## 移动端抓网络请求有点难啊

于是尝试浏览器F12抓网络请求，又尝试移动端代理到电脑抓包，为了抓到包又准备把Fiddler的证书塞进系统证书里（甚至新装了openssl转换.crt证书）。查资料得知最后杀手锏可能要上Frida或者Xposed模块绕过APP的SSL Pinning。总之越搞越深入越复杂，感觉有点超出我的纲了。

## “注意看这个域名”

盯着Fiddler从移动端抓到的网络请求（还是透传状态，只能看到请求的域名，看不到具体URL），发现有几个`*.gztv.com`比较可疑，最后试出来是
```
单个回放的页面的链接：
https://load.gztv.com/plusshare/#/articleDetail?id=按时间递增的十六位数字
整个栏目的回放列表页面：
https://load.gztv.com/plusshare/#/topicDetail?id=五位数字
```
也就是三级域名部分全变成了`load`
